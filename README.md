# @c9up/neutrino

Protocol Buffers and gRPC for the Ream framework.

Neutrino gives Ream a schema-enforced, cross-language contract: one `.proto`
shared by the server and its non-JS clients (mobile apps, Go or Rust services),
instead of a JSON shape documented by hand.

It is additive. JSON stays the default for the web path, and an application that
does not use Neutrino never installs it.

## Status

Here: the codec (schemas from descriptor sets or generated files, encode /
decode over them) and unary gRPC on the Ream application's HTTP port. Streaming
methods, gRPC-web and protobuf over REST land in later releases.

## Schemas

Neutrino reads compiled schemas, not `.proto` text:

- a binary `FileDescriptorSet`, as `buf build -o app.binpb` or
  `protoc --include_imports --descriptor_set_out=app.binpb app.proto` writes it;
- the file descriptors `protoc-gen-es` generates (its `file_*` exports), which
  also give you typed messages.

Messages are [`@bufbuild/protobuf`](https://github.com/bufbuild/protobuf-es)
messages: no code generated at runtime, unknown fields kept, a recursion limit
on decode.

## Use

```ts
import { create } from "@bufbuild/protobuf"
import { Protobuf } from "@c9up/neutrino"
import { file_echo, SayRequestSchema } from "./gen/echo_pb.js"

const protobuf = new Protobuf({ files: [file_echo] })

const bytes = protobuf.encode(SayRequestSchema, create(SayRequestSchema, { text: "hi" }))
const request = protobuf.decode(SayRequestSchema, bytes)

protobuf.message("echo.SayRequest") // a schema by type name
protobuf.method("/echo.Echo/Say")   // a method by gRPC path: input, output, kind
```

Bytes that do not decode — truncated, malformed, invalid UTF-8, nested too deep —
raise `InvalidMessageError` (`E_NEUTRINO_INVALID_MESSAGE`), the error a transport
answers with a client error. Two sources that declare the same type differently
raise `DuplicateTypeError` instead of one silently replacing the other.

## Generating code

Typed messages and services come from `protoc-gen-es`, run by `buf` — both
install from npm, nothing to set up on the machine:

```sh
pnpm add -D @bufbuild/buf @bufbuild/protoc-gen-es
```

```yaml
# buf.yaml
version: v2
modules:
  - path: proto
```

```yaml
# buf.gen.yaml
version: v2
plugins:
  - local: protoc-gen-es
    out: app/generated
    opt:
      - target=ts
      - import_extension=js
```

```sh
pnpm buf generate                  # proto/*.proto → app/generated/*_pb.ts
pnpm buf build -o proto/app.binpb  # the descriptor set, if you load one
```

It is a step on the server side only: the generated files are ordinary
modules, committed or rebuilt like any other source, and nothing reaches the
browser that needs a build to run. Loading the generated files and a
descriptor set built from the same `.proto` together is fine — they are
compared on what affects the wire, not on the source positions `buf` keeps.

## In a Ream application

```ts
// reamrc.ts
providers: [() => import("@c9up/neutrino/provider")]

// config/protobuf.ts
import { defineConfig } from "@c9up/neutrino"

export default defineConfig({
  descriptorSets: [app.makePath("proto/app.binpb")],
})
```

The schemas load at boot, so a missing file or a conflict stops the start
rather than the first request. The instance is bound as `protobuf` and is
reachable from `@c9up/neutrino/services/main`.

## gRPC

Services implemented in TypeScript are served on the application's HTTP port:
a request whose content-type is `application/grpc` is a gRPC call, anything
else is HTTP as before. When the native server's rate limiter and security
filter are configured, they apply to gRPC calls too, before the message is
read.

```ts
// start/grpc.ts — a preload
import { GrpcError, GrpcStatus } from "@c9up/neutrino"
import grpc from "@c9up/neutrino/services/grpc"
import { EchoService } from "#generated/echo_pb.js"

grpc.service(EchoService, {
  async say(request, context) {
    if (!context.metadata.authorization) {
      throw new GrpcError(GrpcStatus.UNAUTHENTICATED, "sign in first")
    }
    return { text: request.text }
  },
})
```

- With a service generated by `protoc-gen-es`, requests and replies are typed
  from the `.proto`. A service from a descriptor set is reached with
  `protobuf.service("echo.Echo")`.
- The middleware and the router never see a gRPC call: protect it with
  interceptors (below).
- A `GrpcError` is answered with its status and message. Any other error is
  answered `INTERNAL` without its message, and reported (to `console.error`
  unless `onError` says otherwise).
- Unary methods only: implementing a streaming method is refused at
  registration.

### Interceptors

An interceptor runs around every call it is registered for — `grpc.use()` for
all of them, `{ interceptors }` for one service — before the request is even
decoded. It refuses a call by throwing a `GrpcError`, lets it through by
returning `next()`, and hands the method a value through a `GrpcContextKey`.
A call to a method nobody serves is answered `UNIMPLEMENTED` without running
any.

Two come with the package, both taking the protecting object structurally:

```ts
import app from "@c9up/ream/services/app"
import auth from "@c9up/warden/services/main"
import { bearerAuth, rateLimit } from "@c9up/neutrino"

// Needs blackhole's rateLimit.store: that is what counts outside an HTTP
// request. Same store and same key — the client IP — so a client has one
// budget for its HTTP requests and its gRPC calls.
grpc.use(rateLimit(await app.container.make("blackhole")))

const signedIn = bearerAuth(auth, { guard: "jwt" })
grpc.service(
  AccountService,
  { me: (_request, context) => ({ id: signedIn.user(context).id }) },
  { interceptors: [signedIn.interceptor] },
)
```

`bearerAuth` answers `UNAUTHENTICATED` to a call without a valid
`authorization: Bearer <token>`, and `signedIn.user(context)` fails closed in a
method it did not protect. `rateLimit` answers `RESOURCE_EXHAUSTED`.

In production, terminate TLS at the reverse proxy and forward gRPC as
plaintext HTTP/2 to the same port the HTTP traffic goes to. With nginx:

```nginx
server {
  listen 443 ssl;
  http2 on;
  location / {
    if ($content_type ~ "^application/grpc") {
      grpc_pass grpc://127.0.0.1:3000;
    }
    proxy_pass http://127.0.0.1:3000;
  }
}
```
